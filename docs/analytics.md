# Аналитика портала (GA4)

## Включение

1. В GA4 создайте Web stream. Укажите его `G-…` в `VITE_GA_ID` при сборке портала (GitHub Actions variable / настройки хостинга). Пустое значение отключает загрузку Google tag.
2. В Dashboard откройте **Settings → Analytics → Google Analytics 4**. Введите Measurement ID того же потока (`G-YZTVDT5QTR`) и API secret, включите интеграцию и сохраните. Секрет создаётся в Google Analytics → Администратор → Потоки данных → поток сайта → Секреты API Measurement Protocol. Оба значения хранятся в БД, секрет зашифрован и скрыт в ответах API. Серверные `.env` и `config.yml` для GA4 не используются.
3. Настройки применяются автоматически без перезапуска. Пока интеграция не настроена или выключена, miniapp и оплаты работают без серверной аналитики. При выключении очередь приостанавливается; после включения возобновляется в пределах срока доставки. Пустое поле секрета при повторном сохранении сохраняет прежнее значение. Серверная схема очереди покупок должна быть развёрнута вместе с кодом аналитики.
4. В настройках Enhanced measurement отключите автоматические просмотры по изменениям истории: портал отправляет `page_view` самостоятельно. Также отключите автоматический сбор форм, исходящих кликов и поиска: авторизация, ссылки оплаты и подписок могут содержать приватные параметры. Эти автоматические события не нужны для описанной ниже воронки.
5. Добавьте платёжные домены в List unwanted referrals. При использовании зеркал настройте cross-domain measurement для своих доменов. Текущий аварийный редирект сохраняет UTM, но перенос GA cookies между доменами автоматически не гарантируется; такой переход нужно проверить отдельно.
6. Создайте event-scoped custom dimensions `payment_provider`, `payment_type`, `purchase_kind`, `error_code`, если они нужны в отчётах. Не регистрируйте ID транзакции как custom dimension. `purchase` — основное ключевое событие; `payment_redirect` можно пометить отдельно для оценки переходов.

## События

| Событие | Момент |
|---|---|
| page_view | Страница или вкладка кабинета; повторы одного адреса подавляются |
| sign_up | Успешная регистрация по email |
| login | Успешный вход по email или Telegram |
| view_item_list | Показ доступных вариантов оплаты (по событию на вариант, валюты не смешиваются) |
| select_item | Выбор варианта тарифа/оплаты |
| begin_checkout | Запрос на создание денежного счёта |
| invoice_created | Сервер вернул счёт |
| payment_redirect | Нажатие перехода на оплату; не доказывает загрузку сайта провайдера |
| checkout_error | Ошибка создания счёта |
| purchase | Сервер подтвердил денежную оплату |
| credits_checkout / credits_purchase | Оплата бонусами, без денежной выручки |

Фильтруйте воронку по пользователям/сессиям, а не только числу событий: пользователь может создать несколько счетов. `purchase_kind=renewal` означает явно выбранный профиль продления; `new` — покупку без явного профиля, не обязательно первую покупку пользователя.

## Источники и отчёты

Размечайте внешние ссылки: `?utm_source=telegram&utm_medium=social&utm_campaign=autumn&utm_content=channel_post`.
Не добавляйте UTM к внутренним ссылкам. Используйте стабильные названия без персональных данных. Портал сохраняет допустимые рекламные параметры в аналитическом URL, убирая остальные параметры и hash. Внешний referrer передаётся только как домен.

GA4 → Acquisition: сравнивайте First user source/medium (первое привлечение) и Session source/medium (текущее посещение). В Explore создайте воронку `page_view → sign_up → begin_checkout → payment_redirect → purchase`; для существующих пользователей используйте вариант без обязательной регистрации. В Ecommerce purchases смотрите тарифы, число покупок и выручку.

При создании счёта портал передаёт только GA `client_id` и `session_id`. Сервер сохраняет цену/валюту/тариф из своей конфигурации. Событие покупки отправляет только сервер, даже если клиент не вернулся на сайт. Никакие email, Telegram ID, JWT или ссылки подписок не входят в payload.

## Очередь и ограничения

`web_analytics_purchases` хранит событие в одной транзакции со счётом. Подтверждение платежа сохраняет время независимо от результата выдачи подписки. Фоновая задача miniapp проверяет очередь каждые 15 секунд; блокировки строк разделяют работу между экземплярами. Ошибки сети/HTTP повторяются с задержкой до часа. Успех отмечается `sent_at`. После 71 часа от подтверждения неотправленная запись получает `last_error=expired` и остаётся для проверки.

Повторная отправка после сбоя между HTTP-ответом и записью в БД возможна: одинаковый `transaction_id` позволяет GA4 подавлять дубликаты. HTTP 2xx означает приём запроса, но не гарантирует принятие всех параметров Google. Нужна проверка в GA4. Поздние платежи могут не наследовать источник сессии: Google требует отправки в пределах 24 часов от её начала. Время реального подтверждения не подменяется временем открытия checkout.

Если Google заблокирован и идентификаторы не получены за 300 мс, счёт создаётся без аналитического контекста. Покупка работает, но такая транзакция не отправляется в GA4. Ранее созданные счета автоматически не импортируются. Фактические суммы сверяйте с базой платежей. Интеграция использует текущую модель включения аналитики сайта; если внедряется управление согласием, оно должно управлять и браузерным тегом, и отправкой контекста на сервер.

## Проверка перед запуском

- `node scripts/test-analytics.mjs` и `npm run build` в портале.
- В xray-vpn-bot: `python -m pytest tests/test_web_analytics.py tests/test_payment_delivery_retry.py tests/test_migration_heads.py`.
- В тестовом потоке GA4 откройте UTM-ссылку, зарегистрируйтесь и создайте счёт. Проверьте браузерные события в Tag Assistant/DebugView.
- Оплатите тестовый счёт, закройте портал. Проверьте `sent_at` в очереди и единственный `purchase` с верными валютой, суммой и ID в GA4. Для проверки payload используйте `/debug/mp/collect` (он валидирует, но не записывает события).
- Повторите webhook: число покупок не должно вырасти. Неоплаченный счёт и оплата бонусами не должны увеличивать денежную выручку.

Официальные источники: [Ecommerce](https://developers.google.com/analytics/devguides/collection/ga4/ecommerce), [Measurement Protocol](https://developers.google.com/analytics/devguides/collection/protocol/ga4/sending-events), [Session attribution](https://developers.google.com/analytics/devguides/collection/protocol/ga4/use-cases).
